# balancePackSota 退化分析与优化设计

## 1. 问题定义

目标用例（来自 `tree_1,16_16384,128`）在以下两个配置出现退化：

1. `HRatio=2, kvHead=8`：baseline `0.000043s`，SOTA `0.000047s`
2. `HRatio=4, kvHead=8`：baseline `0.000039s`，SOTA `0.000047s`

从日志可见两者共同特征：

- SOTA 的 `bucket[0]` 中出现多个 `kv=2048` 的长尾 CTA。
- `num_split_per_seq` 从 baseline 的 `17` 下降到 `12`。
- SOTA 没有把这些 2048 CTA 继续拆成 1024，导致长尾残留。

## 2. 当前算法在该用例上的关键计算

## 2.1 参数与状态

在 `kvHead=8` 下：

- `cta_limit = 27`（由 `_bp_cta_limit_by_kvhead` 决定）
- 该用例 SOTA 的 `bucket[0]` 里：
  - `kv` 分布为 `6 x 1024 + 5 x 2048`（共 11 个 CTA）
- `bucket[1]` 为 `16 x 128`
- 总 CTA 数：`N = 11 + 16 = 27`（恰好等于 `cta_limit`）

因此：

- budget 阶段到达上限后会切到 non-budget 判据。
- 后续是否继续拆分，取决于 non-budget 的单步 `gain > 0`。

## 2.2 代价模型

当前成本模型：

$$
C(q, kv)=a\cdot q\cdot HR + b\cdot kv + c\cdot q\cdot kv\cdot HR
$$

其中：

- $a=0.1, b=0.1, c=2.0$
- 对 `bucket[0]`，`q=16`。

分裂时还会加重复 Q 侧代价：

$$
C_{split\_eff}=C(q, kv_{piece,max}) + (k-1)\cdot a\cdot q\cdot HR
$$

## 2.3 HR=2 的逐步数值

先算单 CTA 成本：

- $C(16,1024)=0.1\cdot16\cdot2 + 0.1\cdot1024 + 2\cdot16\cdot1024\cdot2$
- $=3.2 + 102.4 + 65536 = 65641.6$

- $C(16,2048)=3.2 + 204.8 + 131072 = 131280.0$

若对一个 `2048` 做二分（`k=2`）：

- `added_cta=1`
- `dup_q_cost=0.1*16*2=3.2`
- `C_split_eff = C(16,1024) + 3.2 = 65644.8`

但当前 `bucket[0]` 里还有其他 `2048`，即 `max_cost_others=131280`。

因此单步分裂后的新最大成本：

$$
new\_max = \max(131280, 65644.8)=131280
$$

在该区间 `waves` 不变（通常都在同一波次），则：

$$
gain = waves\cdot max\_before - waves\cdot new\_max = 0
$$

当前 non-budget 停止条件是 `gain <= 0` 则不接受动作，所以第一步就停。

结论：不是“不能分”，而是“并列长尾下单步收益为 0，导致不动”。

## 2.4 HR=4 的逐步数值

同理：

- $C(16,1024)=0.1\cdot16\cdot4 + 0.1\cdot1024 + 2\cdot16\cdot1024\cdot4$
- $=6.4 + 102.4 + 131072 = 131180.8$

- $C(16,2048)=6.4 + 204.8 + 262144 = 262355.2$

二分一个 `2048` 后：

- `dup_q_cost=0.1*16*4=6.4`
- `C_split_eff = 131180.8 + 6.4 = 131187.2`
- `new_max = max(262355.2, 131187.2)=262355.2`
- 单步 `gain=0`

所以 HR=4 也同样被“并列长尾 + 单步 gain 门槛”卡死。

## 3. 为什么 baseline 能更充分分割

baseline 的 `balancePack` 不以这套全局 makespan gain 为唯一门槛，它有偏工程化的“按块长拆分/补齐”机制，因此可以把这类尾部继续切开到更高 split 深度（日志里 `max_split_per_seq=17`）。

SOTA 当前实现则是严格的“单步收益驱动”，对并列最大值 plateau 不友好，导致看起来保守。

## 4. 是否属于“没有充分分割导致的退化”

是。

该用例退化并不是算子本身慢，而是调度产物里长尾 CTA 未被进一步细化：

- `5 x 2048` 长尾留在主桶，抬高了 bucket[0] 的 max cost。
- 由于单步 gain=0，算法没有进入“先打破并列最大值平台”阶段。

这就是典型的“可分而未分”的退化。

## 5. 最小侵入优化方案（设计）

## 5.1 设计目标

在不推翻现有全局贪心框架的前提下，补上 plateau 场景的过渡机制。

## 5.2 方案：plateau-unlock（并列长尾解锁）

当满足以下条件时，允许执行“零收益但有结构改进”的动作：

1. non-budget 阶段
2. `waves_after == waves_before`
3. 当前候选来自最大成本集合（`old_cost == max_cost`）
4. 分裂后 `new_max == max_cost`（单步 gain 约等于 0）
5. 但“最大成本 CTA 的数量会下降”（`max_cost_count` 下降）

在这个特判下，把目标从“只最大化 gain”改为字典序：

1. 最小化 `new_max`
2. 若相等，最小化 `new_max_count`
3. 若仍相等，选择 `kv` 更大的候选（优先消解长尾）

## 5.3 为什么最小侵入

1. 不改变原有 cost model 参数。
2. 不引入新全局超参数。
3. 主循环、候选生成、约束判断都复用原结构。
4. 只在 `gain==0` 的 plateau 子空间扩展一个“可接受动作”判定。

## 5.4 预期效果（本用例）

对 `5 x 2048 + 6 x 1024` 的结构：

- 第 1~5 步可逐个把 `2048` 变成 `2x1024`。
- 每一步可能 `gain=0`，但 `max_cost_count` 从 5 递减到 0。
- 平台打破后，后续常规 gain 判据可恢复有效。

结果是更接近 baseline 的充分分割深度，避免长尾残留导致的退化。

## 6. 实施建议

优先顺序：

1. 先加 `plateau-unlock` 字典序判定（不改其他逻辑）
2. 再观察 `tree_1,16_16384,128` 在 HR=2/4/8 的 `max_split_per_seq` 是否回升
3. 最后再评估是否需要额外策略（如仅对 `kv >= 2*L_kv` 的最大值开启）
